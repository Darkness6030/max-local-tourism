## Подключение PostgreSQL в новом релизе

Перед первым обновлением создать `shared/postgres.env` (root:root, 0600) с `POSTGRES_PASSWORD=<случайный hex-пароль>` и добавить в `shared/.env` строку `DATABASE_URL=postgresql+asyncpg://tourism:<тот же пароль>@db:5432/tourism`. Не перезаписывать остальные секреты. Пароль хранится вне релиза. БД не публикует сетевой порт и использует отдельный постоянный volume compose-проекта. Начальная схема создаётся при старте приложения; для будущих изменений структуры нужна миграция.

Старые результаты, существовавшие только в памяти прежнего процесса, автоматически перенести невозможно. История сохраняется для поездок нового релиза. Прерванная при перезапуске генерация получает ошибку с предложением повторить запрос.

Перед обновлениями сохранять резервную копию PostgreSQL через `pg_dump`; не использовать `down -v`. Возврат на прежнюю версию с хранением в памяти скроет историю в UI, но не удалит volume. Релиз `20260924T164433Z` развёрнут 24.09.2026. Проверены реальная генерация, запись результата в PostgreSQL, история и открытие поездки по публичному HTTPS, изоляция пользователей и отсутствие изменений 27 соседних контейнеров. ## Маршрутизация

В HTTPS-блок `/etc/nginx/sites-available/kaktut.ru` добавлен только include `snippets/max-local-tourism-locations.conf`. Он обслуживает точный `/max/app` и префикс `/max/app/`; `/`, `/api/`, `/client/`, `/g/` остаются за прежними сервисами.

Прокси снимает префикс `/max/app/`, uvicorn запускается с `--root-path /max/app`. Этот параметр нужен и для API, и для StaticFiles. Frontend собирается с `APP_BASE_PATH=/max/app`; API находится под `/max/app/api/v1/`, ресурсы — `/max/app/static/`.

Резервная копия nginx до первого подключения: `/opt/max-local-tourism/backups/nginx-20260924T115435Z/kaktut.ru.before.conf`. Перед reload выполнен `nginx -t`. PID master-процесса сохранился: nginx не перезапускался. Проверены ID всех 27 прежних контейнеров, хеши остальных nginx-конфигураций и ответы прежних маршрутов домена.

## Проверка и обновление

```bash
ssh Dental
cd /opt/max-local-tourism/current
docker compose -f deploy/compose.production.yaml ps
docker logs --tail 50 max-local-tourism-app-1
curl --fail https://kaktut.ru/max/app/api/v1/health
```

Все новые выкладки выполняются **через Git**, без загрузки исходников архивами. Локально:

```bash
# После необходимых проверок и просмотра diff:
git add <изменённые-файлы>
git commit -m "Описание изменения"
python3 scripts/deploy.py
```

Команда требует чистого рабочего дерева и ветки `main`, делает `git push origin main`, затем по SSH запускает серверный сценарий из **того же коммита**. На сервере выполняется `git fetch`, проверка принадлежности коммита ветке main и создание отдельного detached worktree. Перед сборкой сохраняется `pg_dump`; Docker пересобирает и заменяет только `app` (`--no-deps`), не перезапуская PostgreSQL и соседние сервисы. После проверки здоровья, публичных ресурсов и авторизации `current` переключается атомарно. При ошибке обновления приложения возвращается предыдущий образ; при ошибке сборки приложение остаётся прежним. Автоматический откат БД не выполняется.

Для чтения private-репозитория сервер использует отдельный read-only GitHub deploy key: `shared/github_deploy_ed25519`. Приватный ключ находится только на сервере (0600), личный токен GitHub туда не передаётся. Ключи хоста GitHub проверяются по официальному HTTPS API и сохраняются отдельно в `shared/github_known_hosts`; используется `StrictHostKeyChecking=yes`. SSH-настройки привязаны только к этому Git-зеркалу.

Узнать действующий коммит:

```bash
ssh Dental 'git -C /opt/max-local-tourism/current rev-parse HEAD'
```

Успешные выкладки записываются в `deployments/<tag>.commit`, резервные копии — в `backups/postgres-<tag>/tourism.dump`. Не нужны `docker compose down`, перезапуски Docker/nginx или изменение конфигурации бота. Push сам по себе не выкладывает приложение; выкладку запускает `scripts/deploy.py`.

`scripts/check_production.py` проверяет страницу и ресурсы, отсутствие гостевого доступа, подпись профиля и закрытые диагностические маршруты. Флаг `--generate` выполняет одну настоящую генерацию, проверяя принадлежность результата. Данные запуска синтетические, подписанные локально серверным токеном; это не сессия реального клиента MAX. Токен и строка запуска не выводятся.

## Откат

Для ручного отката: из каталога предыдущего релиза выполнить `RELEASE_TAG=<предыдущий-tag> docker compose -f deploy/compose.production.yaml up -d --no-deps --wait --wait-timeout 60 app`, без пересборки; после проверки атомарно вернуть `current` на этот каталог. Это затрагивает только `max-local-tourism-app-1`.

Для удаления маршрута первого релиза: удалить только добавленную строку include из HTTPS-блока kaktut.ru, проверить `nginx -t` и выполнить `systemctl reload nginx`. Старую копию файла можно восстанавливать целиком только после проверки, что с момента резервного копирования не было других правок. После отключения маршрута при необходимости остановить только наш compose-проект.

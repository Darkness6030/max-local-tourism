# Настройка городов

Единый каталог — [`src/assets/cities.json`](../src/assets/cities.json). В нём включены только Москва и Санкт-Петербург; новые города в рабочий каталог не добавлены.

Каталог управляет списками на главной, в анкете и профиле, городом по умолчанию, валидацией новых запросов, поисковым запросом геокодера, ориентирами для ИИ, обложками, подписями и региональными подсказками о билетах. Backend отдаёт настройки интерфейсу через `GET /api/v1/app-config`. Изменять Python/TypeScript для подключения города не требуется.

## Как добавить город

1. Добавить объект в массив `cities`. Минимально нужны `id` и `name`. Например, **только образец записи, не включённый в каталог**:

   ```json
   {
     "id": "kazan",
     "name": "Казань",
     "from_label": "из Казани",
     "geocode_query": "Казань, Республика Татарстан"
   }
   ```

2. При необходимости заполнить дополнительные поля из таблицы ниже. Порядок объектов задаёт порядок в списках. Чтобы изменить город по умолчанию, записать его `id` в корневое поле `default_origin`; иначе оставить текущий `moscow`.
3. Проверить файл из корня репозитория:

   ```bash
   .venv/bin/python -m src.cities
   .venv/bin/ruff check src tests
   .venv/bin/pytest -q
   npm --prefix frontend run build
   ```

   Тесты PostgreSQL требуют отдельной `TEST_DATABASE_URL`, как описано в README.

4. Перезапустить локальный backend и обновить страницу. Каталог читается один раз на процесс; hot reload JSON не предусмотрен. Для Docker пересобрать образ приложения: каталог автоматически включается через `COPY src ./src`.
5. Для production использовать установленный Git-процесс: закоммитить полный набор предназначенных изменений, отправить его в `origin/main`, затем запустить `python3 scripts/deploy.py`. Проверить `.venv/bin/python scripts/check_production.py`. Не копировать исходники на сервер вручную. Добавление города не требует миграций БД или настройки бота.

## Поля каталога

| Поле                | Назначение и значение по умолчанию                                                                                                                                                                                                                          |
|---------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `default_origin`    | Корневое поле: `id` включённого города по умолчанию. Обязательное.                                                                                                                                                                                          |
| `cities`            | Непустой массив объектов городов.                                                                                                                                                                                                                           |
| `id`                | Уникальный идентификатор: латинские строчные буквы, цифры и дефис; начинается с буквы. Обязательный.                                                                                                                                                        |
| `name`              | Уникальное русское название, 2–160 символов. Показывается в списках и передаётся в API как `origin`. Обязательное.                                                                                                                                          |
| `enabled`           | `true`. При `false` город недоступен для новых поездок и выбора в профиле.                                                                                                                                                                                  |
| `geocode_query`     | Необязательное уточнённое название с регионом. Без него геокодер получает `name`. Полезно для одноимённых городов; координаты по-прежнему берутся из геокодера.                                                                                             |
| `from_label`        | Подпись с предлогом, например `из Москвы`. Без неё: `из города «Название»`. Не нужно добавлять склонения в код.                                                                                                                                             |
| `hero_image`        | Имя файла в `frontend/src/assets/`, по умолчанию `journey.webp`. Допустимы `.webp`, `.png`, `.jpg`, `.jpeg`. Для своей обложки добавить файл и указать его имя: Vite автоматически включит его при сборке. Если файл отсутствует, UI покажет общую обложку. |
| `hero_alt`          | Альтернативный текст обложки; по умолчанию `Город и загородный пейзаж`.                                                                                                                                                                                     |
| `destination_hints` | Необязательный массив названий ближайших городов для ИИ. По умолчанию пустой. Это ориентиры, а не закрытый список направлений; расстояние и существование предложенного города проверяются отдельно.                                                        |
| `ticket_note`       | Необязательный объект с непустыми `title` и `text`. Региональная справка во вкладке «Дорога», обычный текст без HTML. Без поля блок не показывается.                                                                                                        |

Неизвестные поля, повторяющиеся названия/идентификаторы и подсказки, пустой список и отключённый/несуществующий город по умолчанию отклоняются. Ошибка конфига останавливает запуск до создания сервисов. Не добавляйте в каталог секреты: данные оформления доступны через публичный API.

## Отключение, история и совместимость

Для временного отключения поставить `enabled: false`; если это город по умолчанию, сначала выбрать другой `default_origin`. Сохранённые поездки остаются читаемыми с исходным городом, датами и программой, даже если запись удалена из каталога. При чтении профиля недоступный город заменяется текущим городом по умолчанию; остальные предпочтения сохраняются. UI также исправляет старые черновики в sessionStorage. Исходные записи поездок в БД не переписываются.

`name` остаётся ключом в существующем API и сохранённых профилях ради совместимости. Переименование воспринимается как удаление старого города и добавление нового; для сохранения связей при переименовании нужна отдельная миграция. `id` используется для настройки города по умолчанию, но не заменяет `origin` в запросах API.

`GET /api/v1/app-config` сохраняет массив строк `origins` и дополнительно возвращает `default_origin` (название) и `origin_details` (оформление включённых городов). `/health` показывает тот же список доступных городов. Новые запросы поездок, проверки направления и записи профиля принимают только включённые города; неизвестный или отключённый город даёт HTTP 422. OpenAPI описывает `origin` строкой и отсылает к актуальному `/app-config`, вместо статического enum.

## Что не требуется для нового города

Отдельные фотографии, билетная справка, подсказки ИИ и готовые маршруты необязательны. Без них работает обычная генерация поездки с общей обложкой, а пустой раздел готовых маршрутов скрывается.

Четыре редакционных маршрута с программами, фотографиями и источниками остаются в `src/assets/trip-presets.json`. Они показываются только для своего `origin`. Настройка редакционных маршрутов и карточек по настроению описана в [PRESETS.md](PRESETS.md). Новые редакционные программы требуют отдельного наполнения и проверки фактов; добавление города не создаёт их автоматически и не переносит в него московские или петербургские маршруты.

Сохраняются общие ограничения продукта: города России, 1–3 дня, ручное направление строго ближе 600 км по прямой; радиус рекомендаций задаётся профилем. Покрытие погоды, расписаний, фото и гостиниц зависит от провайдеров. Сервисный календарь (`today`, дата по умолчанию, горизонт валидации) остаётся в `Europe/Moscow`; время рейсов показывается в локальном времени станций из ответов расписаний, без перевода всех регионов в московское время.

## Проверки

`tests/test_city_catalog.py` использует временный конфиг с тестовым городом: проверяет новый город по умолчанию, отключение прежнего, все границы API, геокодер, ИИ без подсказок и чтение старых профилей/поездок. Рабочий JSON эти тесты не меняют.

Браузерные проверки запускаются на локальной сборке:

```bash
.venv/bin/python scripts/check_city_config_ui.py --base-url http://127.0.0.1:8001
.venv/bin/python scripts/check_profile_ui.py --base-url http://127.0.0.1:8001 --browser webkit
.venv/bin/python scripts/check_presets.py --base-url http://127.0.0.1:8001
```

Первая проверка подменяет публичный конфиг только в браузере: новый город без контента, старый профиль/черновик, выбор города на трёх экранах и время рейсов другого часового пояса. Реальные провайдеры и MAX в этих проверках не вызываются.
